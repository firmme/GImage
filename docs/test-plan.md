# GImage 测试计划与验收矩阵

本文把规格书 §10（性能验收）、§14（测试矩阵 / 发布验收）与 §9（批处理安全）转成可执行、可勾选的用例。规格书中的性能数字是**目标而非承诺**，验收以 P95、峰值和长时间稳定性为准。

## 状态约定

| 状态 | 含义 |
| --- | --- |
| 未执行 | 尚未运行；当前所有用例均为该状态 |
| 通过 | 已按步骤执行并保留证据（日志、截图、基准数据、commit） |
| 阻塞 | 因功能未实现、环境缺失或依赖不可用而无法执行；需在备注中写明阻塞原因 |

> 下表是人工与端到端验收记录，仍为“未执行”。2026-11-18 已执行 workspace 单元测试，76 项通过，详见 [开发进度](progress.md) 和 [原始测试日志](test-results-2026-11-18.log)；单元测试结果不等同于本表验收通过。

| 图像后端 | `ImageEngine::name()` / `version()`、实际 `CodecCapabilities` |

| 样本集 | 样本路径、生成方式、数量、总大小 |
| 测量工具 | 任务管理器 / PerfView / 自建计时日志（注明） |

## 七、已知的规格 ↔ 实现差距（执行时重点确认）

- 规格首选 libvips；v1 使用纯 Rust `image` 后端，编解码能力与色彩处理存在差异（见 [ADR 0002](adr/0002-image-engine.md)）。
- 当前打开的目录已有变更监听。重启会显示中断任务，并保留现场供核对，应用不会自动重跑文件操作。
- 规格要求批量删除走回收站并二次确认；当前未实现。
- 规格的 M6 GPU 画布与 RAW/PSD、动画播放、云同步均不在当前实现范围。
- 输出目录冲突策略 / 原子写已有实现和引擎单测；IO-08、BAT-05、BAT-06 的端到端验收仍待执行。
