# ADR 0004：缩略图缓存

## 状态（Status）

已接受（v1），2026-11-18；缓存组件已实现，尚未接入 UI。相关：[ADR 0001](0001-workspace-and-layering.md)、[规格书 §7](../spec.md)。

## 背景（Context）

网格滚动必须在图片解码较慢时仍然流畅，同时不能无限占用内存或磁盘。源文件可能被外部程序替换、编辑或移动；进程也可能在写缓存时崩溃。缓存必须能自行判断“这份缩略图是否仍对应当前源文件”，且不能因为缓存损坏影响浏览。

## 决策（Decision）

采用两级缓存（`crates/cache`）：

1. **内存 LRU**：按字节预算淘汰最久未使用的条目；单张图超过整个预算时不入内存缓存。
2. **磁盘缓存**：缩略图目录中一个缩略图一个文件，读取顺序为内存 → 磁盘 → 未命中；磁盘命中会回填内存。

### 缓存键

```rust
pub struct ThumbKey {
    pub path_hash: u64,  // 规范化路径的哈希
    pub file_size: u64,
    pub mtime_ns: i64,
    pub max_edge: u32,   // 160 / 320 / 640
    pub version: u32,    // 缩略图流水线版本
}
```

- 磁盘文件名 = 对整个 `ThumbKey` 再做一次 64 位哈希后的 16 进制串，扩展名 `.gthm`。
- 任一字段变化都会产生新的键，因此源文件被替换、修改时间变化、切换尺寸档、升级流水线都会自然失效，无需额外失效表。
- `path_hash` 使用 `DefaultHasher`（非加密哈希）；缓存不是安全边界，碰撞最多导致一次错误的旧图命中校验失败，不应依赖它做访问控制。
- 路径必须是调用方规范化后的路径；移动/重命名文件会因路径变化而生成新键，旧条目由容量清理回收。

### 磁盘文件与校验

文件头固定 33 字节：

| 偏移 | 内容 |
| --- | --- |
| 0..4 | magic `GTHM` |
| 4 | 格式版本（当前 1） |
| 5..9 | `max_edge`（u32 LE） |
| 9..17 | `file_size`（u64 LE） |
| 17..25 | `mtime_ns`（i64 LE） |
| 25..29 | 图像宽度（u32 LE） |
| 29..33 | 图像高度（u32 LE） |

读取时校验 magic、版本、`max_edge`、`file_size`、`mtime_ns`，并要求宽高在 1..=16384、像素字节数不超过 256 MB；任一不符或读不完整就删除该文件并当作未命中。`ThumbKey.version`（`CACHE_VERSION`）变化会改变文件名，因此旧版本缓存不会被读取。

### 写入与清理

- 先写同目录临时文件（`<hash>.gthm.tmp`），`sync_all` 后 `rename` 原子替换；失败则删除临时文件。崩溃最多留下 `.tmp`，启动时统一清理。
- 磁盘写入是 best-effort：失败只记 `tracing::warn!`，不影响浏览。
- 内存预算默认 64 MB（设置可调 16–512 MB）；磁盘软上限默认 2 GB（设置可调 128–10240 MB）。
- `prune(max_bytes)` 按文件 mtime 从旧到新删除直到低于上限；`clear()` 同时清空内存与磁盘；`stats()` 暴露命中数、条目数、字节数。容量清理目前需要调用方/设置页触发，尚未自动定时执行。
- 缓存目录：`%LOCALAPPDATA%\GImage\thumbs\`。

## 后果（Consequences）

- 文件修改时间粒度、大小写路径差异等由文件系统决定；若外部工具在极短时间内以相同大小和 mtime 替换文件，可能命中旧缩略图。缩略图流水线变更时必须递增 `CACHE_VERSION`（或实现等价的键版本升级）。
- 缓存文件包含解码后的像素数据，清理 `thumbs\` 即可释放空间并强制重建；退出应用后删除是安全的。
- 没有跨进程锁：同一缓存目录被多个实例同时写入时，原子重命名保证文件完整，但最后写入者胜出；当前按单实例使用设计。
- `prune` 只按磁盘文件 mtime 淘汰，不感知内存 LRU；两级预算独立。
