# ADR 0005：批处理与文件安全

## 状态（Status）

已接受（v1），2026-11-18；任务队列已实现，原子导出与输出策略待实现。相关：[ADR 0002](0002-image-engine.md)、[ADR 0004](0004-thumbnail-cache.md)、[规格书 §9](../spec.md)。

## 背景（Context）

批量转换/重命名可能一次影响上百个文件。若并发无上限会耗尽内存；若强制终止线程会留下半写文件；若默认覆盖目标会丢失数据。规格书要求：有界队列、进度、取消、冲突策略、原子输出、原图不被修改，且批量删除必须可恢复或二次确认。

## 决策（Decision）

### 有界队列

`gimage_task_queue::run_batch`：

- 固定数量 worker 从共享索引领取任务，内存中只保留任务列表和结果，不随队列增长而无界创建线程。
- `BatchOptions { concurrency, retry_failed }`，默认并发 **2**（普通机器上的起点），实际并发 clamp 到 1–16，且不超过任务数。
- 可选“失败重试一次”：仅在未取消时，等待 120 ms 后重试；仍失败则记入失败列表。
- 逐项事件只携带下标：`Started` / `ItemStarted` / `ItemSucceeded` / `ItemFailed` / `Progress` / `Finished`，UI 用自己的行映射展示，避免把路径或像素穿过事件通道。
- 单项失败不会终止整批；`BatchOutcome` 汇总 `total` / `succeeded` / `failed[]` / `canceled` / `elapsed`，状态标签为“已完成 / 部分失败 / 失败 / 已取消”。

### 协作式取消

- `CancellationToken` 是共享的原子布尔值；worker 在领取新任务前检查，长循环内部也应轮询。
- 取消**不杀线程**：正在编码的那一项会完成并清理临时文件，然后不再领取后续项。取消延迟上界 ≈ 一个最慢单项。
- 已开始但未完成的项不会产生可见输出；临时文件必须在成功/失败/取消路径上都清理。

### 原子导出与原图保护

导出流程固定为：

```text
读取源文件（只读）→ 渲染到 RgbaImage → 编码到同目录临时文件
→ flush / sync_all → 关闭 → 原子 rename 到最终路径
```

- 源文件只读打开，导出目标与源路径分开解析；**任何情况下不得先删除或截断源文件**。
- 临时文件与目标位于同一目录/文件系统，保证 `rename` 原子性；跨卷移动不满足原子性，必须避免。
- `OutputPolicy`：
  - `AutoRename`（默认）：目标存在时生成 `name (2).ext`、`name (3).ext` …，绝不覆盖；
  - `SkipExisting`：目标存在则跳过并计入结果；
  - `Overwrite`：破坏性操作，UI 必须先确认，再执行原子替换。
- `MetadataPolicy` 当前只有 `Strip`：输出为方向归一化后的像素，不携带原始 EXIF 元数据。
- 批量删除不在本 ADR 的已实现范围内。规格要求优先走系统回收站，永久删除必须二次确认；实现前不得在 UI 提供“直接永久删除”。

## 后果（Consequences）

- `gimage-task-queue` 的队列、并发、重试、取消与结果汇总已实现并有单元测试。
- `crates/engine` 的 `write_atomic`、`export_image`、`unique_destination`、`resolve_destination` 仍是未实现的脚手架（`todo!()` 或直接返回输入）；在这些函数完成前，**原子导出和输出冲突策略尚不成立**，不得宣称批量转换可用。
- 取消发生在编码中时，取消延迟取决于单个文件的编码时间；UI 应显示“正在完成当前项”。
- 重试只适合幂等操作；工作函数必须在每次尝试前清理自己的临时文件，否则重试可能留下垃圾。
- 批处理状态目前只存在于内存，进程退出后不恢复；规格书要求的“退出重启恢复”尚未实现。
- 批量删除、回收站集成与二次确认仍是 TODO，需在实现时补充独立的安全评审与测试。
